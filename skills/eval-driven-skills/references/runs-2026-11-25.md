## The SwiftData finding (the story to tell)

Case: add `priority: Int` with default 0 to a `@Model` of an app already in the store — a real
upgrade-install crash. Both arms answered `var priority: Int = 0`, the code that crashed real installs.
Trace: the model invoked the user-level `swiftdata` skill, not `mobile-feature-delivery`.
`~/.claude/skills/swiftdata/SKILL.md:100-101` says "do not make every scalar optional… keep
required scalars nonoptional when initializers, defaults, or migrations" cover it — which
contradicts the incident. Two lessons:
1. A rule that exists in a skill is not a protection until an eval shows it fires.
2. Skills compete: a generic reference skill with a better-matching name wins the trigger. Fixes are
   in the description (trigger) and in the conflicting skill — not in more rule text.

## Harness lessons

- `claude plugin eval` was early-access on this account; `--trust-plugin` / `--no-publish` don't
  exist in Claude Code 2.1.220 → keep the case format, run with `run_evals.py`.
- Graders default to `with-only`: quality graders must be `arm: both`, otherwise W/OUT is unscored
  and there is no Δ.
- Cases that write files need `max_turns` ≥ 25.
- One run per arm is noise for small Δ: confirm any Δ < 0.3 with `--runs 3` before acting.
- A run's cost is $4–7 for ~10 cases at 1 run — budget the biweekly audit at ~$15.

decision. Evals surface that as a conflict between canon and rule — resolve it with the owner, then
fix either the skill or the rubric.
